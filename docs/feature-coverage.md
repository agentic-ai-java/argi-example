# Behavioral coverage

This inventory describes the source tree as reviewed on 2026-10-15. A website chapter link does not mean every feature in that chapter is implemented. None of the entries below is a runtime pass claim.

## Reading the inventory

- **Demonstrated behavior** identifies the actual code path, including explicit fixtures and failure scenarios.
- **Additional entry points** are separate runnable scenarios in an existing Maven module; they do not create extra Maven modules.
- **Limits** identify deliberately small examples, incomplete feature families and integration behavior that still requires validation.
- All new and existing Java source imports are explicit. The catalog check rejects wildcard imports in main and test sources.

## Remaining feature families

The repository does not claim complete coverage of the upstream public API. In particular, production recovery under concurrent writers, distributed scheduling, full A2A server/task lifecycles, all MCP resource/prompt/authentication operations, all built-in tools, all document parsers, advanced retrieval/reranking, and live audio/video provider behavior are outside the implemented scenarios. Backend profiles configure integrations but do not prove their connectivity or behavioral parity.

## Verification boundary

The source inventory and runtime validation serve different purposes. Local builds,
model calls and the Studio HTTP/SSE workflow were executed on 2026-10-15;
[validation results](compatibility.md#verification-boundary) record their outcomes.
Some gateway-backed runs remain unsuccessful, and external backend services were
not started. Performance, load, capacity, chaos and backend interoperability are
unverified. CI checks the catalog, Java formatting and compilation. Runtime behavior is
inspected through documented entry points; no test suites or coverage gates remain.

Primary evidence is the sibling `argi-website/docs/frameworks`, `argi/argi-api`, `argi/argi-graph-core`, `argi/argi-agent-framework`, and `argi-extensions` source tree. Pinned dependency revisions are recorded in [compatibility.md](compatibility.md).
